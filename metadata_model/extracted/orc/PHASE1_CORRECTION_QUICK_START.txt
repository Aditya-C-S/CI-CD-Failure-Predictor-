WHAT WAS FIXED?
═══════════════
Prevented silent reuse of stale graphs when processing different SHAs of the same repo.

Problem:  post-sync verification only checked node_count > 0
          (Not sufficient to prove exact SHA)

Solution: Multi-layer verification
          1. Checkpoint keying: (repo_id, target_sha) — independent storage for each SHA
          2. Enhanced docs: Explained limitation & mitigation in code comments
          3. Regression test: Validates stale graphs for different SHAs are rejected

HOW IT WORKS
════════════

Before (Gap):
  Request 1: process_commit(repo_x, SHA-A)  → Sync → Checkpoint.save(repo_x, A)
  Request 2: process_commit(repo_x, SHA-B)  → Verify node_count > 0 ✓ → DONE
  Problem:   Nodes could be stale from SHA-A, but verification passed silently ❌

After (Fixed):
  Request 1: process_commit(repo_x, SHA-A)
             → Checkpoint.get(repo_x, SHA-A) → not found
             → Sync → Checkpoint.save(repo_x, SHA-A, COMPLETE)

  Request 2: process_commit(repo_x, SHA-B)
             → Checkpoint.get(repo_x, SHA-B) → not found
               [Key doesn't match because (repo_x, SHA-B) ≠ (repo_x, SHA-A)]
             → Sync (forced to re-sync, not reused from SHA-A)
             → Checkpoint.save(repo_x, SHA-B, COMPLETE)
  
  Result:    Each SHA has independent checkpoint, no stale reuse ✅


VERIFICATION LAYERS
═══════════════════

Layer 1: Checkpoint Keying (Primary Defense)
└─ Key: (repo_id, target_sha)
└─ Different SHAs = different checkpoints
└─ Cannot accidentally query wrong SHA checkpoint
└─ Location: src/storage/checkpoint.py (SQL PRIMARY KEY)

Layer 2: Post-Sync Verification (Secondary Check)
└─ Checks: node_count > 0 for repo_id
└─ Prevents: Reporting SYNCHRONIZED when graph failed to sync
└─ Cannot: Detect which exact SHA nodes represent (graph engine limitation)
└─ Location: src/adapters/graph_adapter.py, _verify_sync_to_sha()

Layer 3: Regression Test (Validation)
└─ Tests: Different SHAs don't incorrectly share checkpoints
└─ Prevents: Silent reuse of stale graphs in future regression
└─ Location: tests/test_phase1_db_and_sync_verification.py


KNOWN LIMITATIONS (Documented)
══════════════════════════════

1. Graph Engine Cannot Store SHA Metadata
   → Cannot query "which SHA is this graph for?"
   → Mitigation: Checkpoint keying ensures SHA isolation
   → Status: Accepted (graph-doc-gen not modified)

2. Partial Sync Not Detected
   → Node count > 0 doesn't prove complete sync
   → Mitigation: Acceptable for Phase 1
   → Status: Known limitation

3. Same SHA, Different Graphs Not Distinguished
   → Cannot detect if two syncs produce different results
   → Mitigation: Graph engine responsible for determinism
   → Status: Graph engine responsibility
