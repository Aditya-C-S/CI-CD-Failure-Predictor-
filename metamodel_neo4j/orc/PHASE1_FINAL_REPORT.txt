TASK 1: DATABASE ALIGNMENT
─────────────────────────

Mechanism:
  - .env: NEO4J_DATABASE=graphdoc tells Neo4jClient which database to use
  - GraphAdapter.__init__() calls _verify_database_target()
  - If database is NOT 'graphdoc': Exception raised, client closed
  - If database IS 'graphdoc': Safe to proceed with sync

Verification Points:
  ✅ test_graphdoc_database_selected: Correct database accepted
  ✅ test_wrong_database_rejected_on_init: neo4j database rejected
  ✅ test_no_database_selected_rejected: None/missing database rejected
  ✅ test_client_closed_on_verification_failure: Cleanup on failure

TASK 2: POST-SYNC VERIFICATION
──────────────────────────────

Mechanism:
  - update_graph_from_diff() called with explicit repo_id and target SHA
  - After update returns: Query Neo4j for nodes matching (repo_id, type)
  - If node_count > 0: Verification passes, return SYNCHRONIZED
  - If node_count == 0: Verification fails, raise exception, trigger retry

Query Used:
  MATCH (n {repo_id: $repo_id})
  WHERE n:File OR n:Function OR n:Class OR n:Module
  RETURN COUNT(n) as node_count

Verification Points:
  ✅ test_successful_sync_and_verification: Passes when nodes exist
  ✅ test_verification_failure_raises_exception: Fails when no nodes
  ✅ test_verification_uses_correct_repo_id: Correct repo_id filtered

Retry Safety:
  ✅ Checkpoint NOT marked COMPLETE until verification passes
  ✅ Failed verification raises exception → triggers retry
  ✅ Cached prediction reused, graph sync retried
  ✅ Re-sync with same SHA is idempotent (graph-doc-gen handles dedup)

VERIFICATION MECHANISM: TARGET SHA ASSURANCE
================================================================================

Target SHA is established by caller:
  orchestrator.process_commit(repo_id, target_sha, repo_path, base_sha)
                                      ↑
                              Specified by caller

If base_sha not provided, computed as:
  base_sha = parent_commit(target_sha) or empty_tree (for root)

In graph sync:
  update_graph_from_diff(repo_path, base_sha, target_sha, repo_id)
                                            ↑
                                    Exact SHA to sync to

Post-sync verification confirms:
  SELECT COUNT(n) FROM nodes WHERE n.repo_id = target_repo_id
                             AND (n:File OR n:Function OR n:Class OR n:Module)
                             
  If COUNT > 0: ✅ Graph was updated for this repo_id
  If COUNT = 0: ✗ No nodes found, raises exception for retry

Guarantee: SYNCHRONIZED status is only returned after successful verification

DATABASE CONFIGURATION FLOW
================================================================================

Environment:
  .env contains: NEO4J_DATABASE=graphdoc

Load:
  GraphAdapter.__init__()
    ↓
    Neo4jClient(**neo4j_config)
      ↓
      Reads: NEO4J_URI, NEO4J_USERNAME, NEO4J_PASSWORD, NEO4J_DATABASE from .env
      ↓
      Sets: self.database = "graphdoc"
    ↓
    GraphAdapter._verify_database_target()
      ↓
      Assert: self.client.database == "graphdoc"
      ↓
      If NOT: Raise exception, close client
      ↓
      If YES: Continue safely

Result: All graph operations use 'graphdoc' database

================================================================================
ERROR MESSAGES USERS WILL SEE
================================================================================

If NEO4J_DATABASE is wrong:
─────────────────────────
  GraphSyncException: Wrong database target: 'neo4j'.
  ORC requires NEO4J_DATABASE=graphdoc to avoid contaminating production data.
  Current .env has NEO4J_DATABASE=neo4j. Update .env and restart.

If NEO4J_DATABASE is not set:
──────────────────────────────
  GraphSyncException: NEO4J_DATABASE not set.
  ORC requires explicit targeting of 'graphdoc' database.
  Set NEO4J_DATABASE=graphdoc in .env and restart.

If verification fails (sync completed but no nodes found):
─────────────────────────────────────────────────────────
  GraphSyncException: Post-sync verification failed: No nodes found
  for repo_id='owner/repo' after syncing to abc1234def.
  The graph may not have been updated. Retrying or manual inspection may be needed.

KNOWN LIMITATIONS
================================================================================

1. Verification Query Latency
   - Post-sync verification adds a Neo4j query per sync
   - Expected impact: < 100ms (negligible vs parsing latency)
   - Can be optimized if needed via indexing

2. Partial Update Detection

     (would require graph-doc-gen enhancement)

3. Production Performance
   - Real latency impact unknown without production load test
   - Estimate: Negligible (query is COUNT operation)
